# Обработка VMware Hosts

## Отдельное приложение PES

```powershell
.\.venv\Scripts\python.exe web_pes_app.py --host 0.0.0.0 --port 8001
```

Страница: **http://127.0.0.1:8001**, по сети — `http://IP_СЕРВЕРА:8001`.
Веб-приложение запускает `mm_pes.py`. Через страницу загружается только выгрузка PES (XLSX).
Загрузка справочников через PES отключена. Справочник серверов используется
из `rsm`, производственная утилизация — из `PU`, выгрузка PES — из `data_pes`.
Выгрузки сохраняются в `data_pes`; выбор выгрузки запоминается в `web_pes_inputs.json`.
Пути справочников берутся из `RSM_FILE` и `PU_FILE` в `mm_pes.py`;
сохранённые в настройках старые пути справочников игнорируются.
По умолчанию ожидаются `rsm/c9d0d891_rsm.xlsx`, `PU/PU.xlsx`
и `data_pes/20260917_160818.xlsx`. Справочники должны находиться в указанных каталогах.

- `log_pes` — отчёт после фильтрации состояний и дедупликации, до порога утилизации.
- `output_pes` — итоговый отчёт с префиксом `MM_`, доступный для скачивания.

PES обрабатывает состояния `["maintenance"]` и `["disconnected"]`, выбирает
дубли по `max_cpu`, затем `cpu_2sigma_usage`. Порог задан в `mm_pes.py`
константой `PU_BORDER` (45%); на странице настройки порога нет.
В отчётах четыре поля: КЭ, node_name, node_state, Производственная утилизация.
HTML: `web/pes.html`. Выбор файлов и отчёты отделены от VMware-приложения.

## Веб-страница

### HTTPS (`web_S_app.py`)

```powershell
# Один раз: создать сертификат для имени и текущих IP этого компьютера
.\.venv\Scripts\python.exe create_https_cert.py
# Запустить HTTPS-сервер
.\.venv\Scripts\python.exe web_S_app.py --host 0.0.0.0 --port 8443
```

Откройте `https://localhost:8443` на сервере или `https://IP_СЕРВЕРА:8443`
с другого компьютера. Используется TLS 1.2 или новее. Сертификат и ключ
по умолчанию: `certs/server.crt` и `certs/server.key`.
Сервер не запускается, если сертификат или ключ отсутствуют либо некорректны.

Для сертификата, выданного вашим удостоверяющим центром (формат PEM):

```powershell
.\.venv\Scripts\python.exe web_S_app.py --cert C:\certs\server.crt --key C:\certs\server.key --port 8443
```

Сертификат должен включать используемое имя/IP в Subject Alternative Name.
Генератор создаёт самоподписанный сертификат на 365 дней. Для доступа без
предупреждения браузера настройте доверие к `server.crt` на клиентских компьютерах
или используйте сертификат доверенного корпоративного центра. Закрытый ключ
`server.key` остаётся на сервере; клиентам его передавать не нужно.
Системное хранилище доверия генератор не меняет, существующие ключи не перезаписывает.
При изменении IP создайте новый сертификат в другом каталоге (`--directory`)
либо используйте стабильное DNS-имя. Дополнительное имя/IP: `--name`.
Для генерации нужен OpenSSL в PATH, Anaconda или указанный через `--openssl`.
В брандмауэре для HTTPS используется TCP-порт 8443.

### HTTP (`web_app.py`)

```powershell
.\.venv\Scripts\python.exe web_app.py
```

На серверном компьютере откройте **http://127.0.0.1:8000**.
На другом компьютере той же сети откройте `http://IP_СЕРВЕРА:8000`
или `http://ИМЯ_КОМПЬЮТЕРА:8000`. Доступные адреса выводятся при запуске.
По умолчанию сервер слушает все IPv4-интерфейсы (`--host 0.0.0.0`).
Сервер работает, пока запущена команда; остановка — `Ctrl+C`.

```powershell
# Запуск для локальной сети
.\.venv\Scripts\python.exe web_app.py --host 0.0.0.0 --port 8000
# Доступ только с этого компьютера
.\.venv\Scripts\python.exe web_app.py --host 127.0.0.1 --port 8000
```

Если Windows блокирует подключение, разрешите входящий TCP-порт 8000
в брандмауэре для локальной подсети и используемого сетевого профиля.
При другом порте измените его и в адресе, и в правиле брандмауэра.
У пользователей сети общий набор файлов, журнал и результаты; вход по паролю
не предусмотрен. Одновременно выполняется одна обработка.

1. В блоке «Входные файлы» загрузите RSM (`.xlsx`), PU (`.xlsx`) и VMware Hosts
   (`.csv` или `.xlsx`). Можно перетащить файл на соответствующий блок.
2. Нажмите «Запустить обработку». Порог утилизации 45% применяется на сервере.
3. Следите за статусом и журналом. Скачайте готовый Excel из блока «Готовые отчёты».

Загрузки сохраняются в `rsm`, `PU` и `data` с уникальными именами; прежние файлы
не перезаписываются. Выбор сохраняется в `web_inputs.json` и восстанавливается
при перезапуске. При первом запуске доступны исходные файлы проекта, если они есть.
Размер одной загрузки — до 200 МБ. Проверка содержимого и обязательных столбцов
выполняется при обработке. Одновременно выполняется одна обработка; загрузка
новых файлов на это время блокируется. Большой RSM может читаться несколько минут.

Результаты доступны в `output`, копия до порога — в `log`.
HTML-страница находится в `web/index.html` и открывается через запущенный сервер.
Дополнительные Python-библиотеки для веб-интерфейса не требуются.

## Запуск из консоли

Установка и запуск в PowerShell из каталога проекта:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
.\.venv\Scripts\python.exe -m unittest -v
```

Входы задаются в `MM_VMware.py`, пути разрешаются относительно файла скрипта:

- `rsm/rsm.xlsx`: справочник имён/IP и КЭ.
- `PU/PU.xlsx`: производственная утилизация по КЭ.
- `data/VmWare Hosts-data-2026-09-15 19_02_37.csv`: выгрузка хостов.

Формируются два файла с общей отметкой времени:

- `log/*-with-CE.xlsx` — после сопоставления и дедупликации, до ограничения `PU_BORDER`.
- `output/MM_*-with-CE.xlsx` — после ограничения `PU_BORDER`.

Оба каталога создаются автоматически. Оба файла содержат четыре выбранных столбца.
`main.py` и `MM_VMware.py` запускают одну обработку.

Для VMware поле `name` используется как `node_name`. Отбираются хосты
с `maintenance_state=inMaintenance` или `connection_state=disconnected`.
В выходном файле сохраняются только `КЭ`, `node_name`, `node_state` и
`Производственная утилизация`. Поддерживается и прежний формат с `node_name`
и `node_state`. Если есть метрики CPU, при повторном имени выбирается строка
с наибольшими `max_cpu`, затем `cpu_2sigma_usage`; без метрик — первая строка.
В приложенной выгрузке повторных имён и метрик CPU нет.

КЭ сопоставляется по короткому имени, затем полному имени/IP; для VMware
предусмотрен поиск по `mgmt_address`. IP-адреса не сокращаются до первого октета.
Существующее правило для повторных ключей справочников — последняя запись.

Сохраняются строки с утилизацией до 45% включительно, а также с неизвестной
утилизацией (исходное правило). Числа от 0 до 1 трактуются как доли;
строки с `%` — как проценты, поддерживается десятичная запятая.

Входные данные: RSM — 873 947 строк; PU — 75 045; VMware — 25 859,
из них 8 341 в обслуживании и 17 518 вне обслуживания, все подключены.
В PU нет пустых/нечисловых значений утилизации или значений вне 0–100%.
Четыре записи PU содержат общий ключ-заглушку `x Не указан` вместо КЭ;
его нельзя считать идентификатором сервера.

Проверенный результат полного запуска: 25 843 хоста сопоставлены с КЭ;
из 8 341 хоста в обслуживании 3 021 исключён по границе утилизации.
В итоговом Excel 5 320 строк, включая 5 без найденных КЭ и утилизации.
Эти 5 строк оставлены по исходному правилу для неизвестной утилизации.
Повторное чтение Excel подтвердило уникальность имён, состояния,
порядок столбцов и соблюдение порога. Пять модульных тестов проходят.
